# Pinzon MVP v0.1

Локальный визуальный архив ссылок для Android. Главный принцип: **сначала сохранить, потом разобраться**.

## MVP

- ручное добавление URL;
- Android Share: приложение получает ссылку из системного меню «Поделиться»;
- объект сохраняется в SQLite до получения метаданных;
- название и изображение загружаются независимо;
- retry: сразу, через 2, 5 и 10 секунд; timeout одной попытки — 10 секунд;
- fallback: `Без названия` и дефолтный кот;
- пользовательское название имеет приоритет над автоматическим;
- Неразобранное = все объекты с `categoryId = null`;
- подборки с уникальными именами без учёта регистра;
- один объект находится максимум в одной подборке;
- визуальная сетка 2 колонки;
- карточка объекта, заметка и открытие исходной ссылки во внешнем приложении;
- массовый выбор, перемещение и удаление;
- удаление подборки переводит её объекты в Неразобранное;
- обнаружение дубликатов с подтверждением принудительного создания;
- локальная работа без аккаунтов и облачной синхронизации.

## Архитектура

```text
ArchiveItem
├── url
├── title
├── titleSource
├── imageUrl
├── imageStatus
├── note
├── categoryId
├── metadataStatus
├── createdAt
└── updatedAt

Archive
├── Неразобранное  -> categoryId = null
└── Подборки       -> categoryId = ID
```

SQLite использует схему v3. При обновлении старой установки выполняется best-effort миграция из `products/boards`: URL, название, изображение, заметка и первая назначенная доска переносятся в новую модель.

## Сборка

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release
```

Требования: Flutter 3.38.1+, Dart 3.10+, Android SDK и Java 17.

## Метаданные

Pinzon делает запрос непосредственно с устройства и использует стандартные HTML Open Graph/HTML title и JSON-LD. Магазины могут блокировать автоматическое чтение страниц, поэтому отсутствие метаданных никогда не блокирует сохранение URL.

Состояние незавершённой загрузки хранится в SQLite. После нового запуска приложения очередь повторно обрабатывает объекты со статусом `loading`.

## Android Share

`MainActivity` принимает `ACTION_SEND` для `text/plain` и `image/*`, корректно обрабатывает cold start и hot start и передаёт URL во Flutter через MethodChannel.

## CI

Основной workflow остаётся в `.github/workflows/build-android.yml`. Release-сборка может использовать постоянный signing key через секреты репозитория; без них CI создаёт временный ключ.
